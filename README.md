# Covenant Compliance Agent

Автономный агент проверки финансовых ковенантов по кредитным договорам.

Система принимает на вход неструктурированный корпус документов (кредитные договоры, аудиторские заключения, досье KYC, служебные записки казначейства) и единый реестр транзакций, после чего по каждому ковенанту каждого заёмщика формирует заключение: соблюдён ковенант или нарушен, каково фактическое значение ограничиваемого показателя и какая операция является решающей для вердикта.

Решение подготовлено для Halyk AI Challenge.

## Быстрый старт

Требуется Python 3.12 или новее. Внешние сервисы, ключи доступа и переменные окружения не используются.

```bash
git clone https://github.com/scumabuse/halyk_hackathon.git
cd halyk_hackathon

python -m venv .venv
```

```bash
pip install -r requirements-dev.txt
```

## Архитектура

Конвейер состоит из девяти последовательных этапов. Каждый этап изолирован в отдельном модуле, принимает и возвращает явные структуры данных и снабжён журналированием на русском языке.

| Этап | Модуль | Назначение |
|---|---|---|
| 1 | [src/dataset.py](src/dataset.py) | Идентификация файлов набора по содержимому |
| 2 | [src/ocr.py](src/ocr.py) | Обнаружение и распознавание страниц без текстового слоя |
| 3 | [src/documents.py](src/documents.py) | Классификация документов, выбор действующих редакций |
| 4 | [src/covenants.py](src/covenants.py) | Разбор Статьи 6 в вычислимую спецификацию |
| 5 | [src/ledger.py](src/ledger.py) | Отбор значимых операций и отнесение их к статьям |
| 6 | [src/related_parties.py](src/related_parties.py) | Определение круга связанных сторон по досье KYC |
| 7 | [src/adjustments.py](src/adjustments.py) | Применение корректировок аудитора, восстановление данных |
| 8 | [src/engine.py](src/engine.py) | Детерминированный расчёт показателей |
| 9 | [src/evidence.py](src/evidence.py), [src/submission.py](src/submission.py) | Определение решающей операции, формирование результата |

Оркестрация выполнена в [main.py](main.py). Вспомогательные модули: [src/logger.py](src/logger.py) — журналирование и сводка предупреждений.

### Спецификация ковенанта как дерево выражения

В публичном наборе встречается восемнадцать различных расчётных формул: коэффициент капиталоёмкости, коэффициент покрытия процентов, условный тест на леверидж, скорректированная рентабельность по EBITDA, потолок отдельной статьи накладных расходов, выручка за отдельный квартал, выручка за вычетом наибольшей из двух статей, доля активов, переданных неограниченным дочерним организациям, и другие.

Жёсткая привязка формулы к номеру пункта неприемлема: состав ковенантов различается между заёмщиками и заведомо изменится в приватном наборе. Поэтому пункт договора опознаётся по характерной формулировке, а результатом разбора является дерево выражения над статьями расходов и доходов:

```python
(r"коэффициент капиталоёмкости", "capital_intensity",
 DIV(S("capex"), ADD(S("opex"), S("rent")))),

(r"Коэффициент покрытия процентов", "interest_cover",
 DIV(SUB(S("revenue"), S("opex")), S("interest"))),
```

Дерево вычисляется в [src/engine.py](src/engine.py) средствами `decimal.Decimal`. Поддержка нового типа ковенанта добавляется одной записью в таблицу `SPEC_LIBRARY` без изменения расчётного кода.

## Модель предметной области

Из 1473 строк реестра к заёмщикам, перечисленным в шаблоне, относятся 673; на значение ковенантов влияют 73 операции. Остальные строки представляют собой наполнитель, не входящий ни в одну статью расчёта.

Наполнитель определяется по двум независимым признакам:

1. **Контрагент.** Наполнитель формируется из общего пула наименований, который используется в том числе на 549 счетах-декоях. Значимые контрагенты привязаны к отрасли заёмщика и на счетах-декоях не встречаются. Состав пула не фиксируется в коде: он вычисляется из самого набора как множество первых слов наименований контрагентов на счетах, отсутствующих в шаблоне. Такой подход сохраняет работоспособность при смене пула.

2. **Описание операции.** Наполнитель содержит суффикс через тире с указанием локации или периода (`— Kyzylorda station`, `— Q3`, `— period 01`). Описания значимых операций не содержат такого суффикса.

Совместное применение двух правил на публичном наборе даёт полноту и точность 73 из 73 без пропусков и ложных срабатываний.

Статьи расходов взаимно исключающи. Платёж связанной стороне не включается в операционные расходы; расходы на персонал и коммунальные услуги не входят в состав операционных, если договор не предусматривает иного. Контрольный пример по счёту ACC-7806: `418 662.44 / 4 204 663.19 = 0.10`, что соответствует эталону, тогда как включение расходов на персонал и коммунальные услуги в знаменатель даёт `0.07`.

## Обработка дефектов исходных данных

Набор содержит систематические дефекты, каждый из которых при наивной обработке приводит к неверному вердикту. Ниже перечислены выявленные дефекты и реализованные контрмеры.

### Несоответствие имён файлов их содержимому

Расширения и имена файлов не отражают содержимое. В публичном наборе реестр транзакций размещён в файле `CASE.ru.md`, шаблон результата — в `master_ledger_2025.csv`, ключ ответов — в `submission_template.json`; часть документов PDF имеет расширения `.txt`, `.csv` и имя `_Thumbs.db`.

Идентификация выполняется исключительно по содержимому: по сигнатуре `%PDF-`, по обязательному набору колонок реестра, по наличию ключа `answers` для шаблона и по структуре `scenarios[*].covenants` для ключа ответов. Имя файла используется только в журнале.

### Недействующие редакции договоров

Редакции 2024 года содержат отметку «НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ … НЕ ПРИМЕНЯЕТСЯ» и иные пороговые значения. По счёту ACC-7801 порог пункта 6.1 в недействующей редакции составляет 1.17x против 0.42x в действующей: применение устаревшей редакции преобразует фактическое нарушение (0.46) в мнимое соблюдение.

Действующей признаётся редакция без отметки, ковенантный период которой совпадает с отчётным годом реестра. Отклонённые редакции с указанием причины отражаются в отчёте.

### Промежуточные аудиторские документы

Ведомости с отметкой «ПРОЕКТ — ПРОМЕЖУТОЧНАЯ ВЕДОМОСТЬ … НЕ ЯВЛЯЕТСЯ ОКОНЧАТЕЛЬНОЙ ПОЗИЦИЕЙ АУДИТОРА» исключаются из обработки.

Окончательный вывод не всегда содержится в примечаниях к отчётности. По счёту ACC-7201 примечание содержит отсылку к отдельному отчёту о выполнении согласованных процедур № AR-2025-0634, в котором зафиксирована переклассификация суммы 592 296.10 в состав процентных расходов. Без учёта этого документа коэффициент покрытия процентов составляет 1.94 вместо 1.68.

### Отклонённые переклассификации

Аудитор отдельно фиксирует переклассификации, которые были рассмотрены и отклонены с сохранением первоначальной классификации. Условия договоров прямо исключают такие корректировки из расчёта. Соответствующие формулировки распознаются отдельным правилом и не применяются.

### Документы-имитации

Комплаенс-регламент по счёту ACC-7801 структурно повторяет досье KYC, однако содержит прямое указание на то, что не является клиентским досье и не содержит выводов по конкретному клиенту. Дополнительно в документ включены недостоверный субсчёт `ACC-7801-05` и посторонняя денежная сумма. Документ классифицируется как нерелевантный; регулярное выражение для идентификации счёта не захватывает форму субсчёта.

### Страницы без текстового слоя

Четыре документа содержат существенные для расчёта таблицы в растровом виде.

| Документ | Содержимое растровой страницы |
|---|---|
| Досье KYC, ACC-7802 | Таблица долей голосующих прав, порог 25.0 % |
| Досье KYC, ACC-7806 | Досье целиком, три страницы |
| Досье KYC, ACC-7809 | Доли активов в залоге, правило признания дочерней организации неограниченной |
| Аудиторское заключение, ACC-7804 | Разовые статьи EBITDA, порог существенности 300 000.00 |

Страница классифицируется как растровая при наличии изображения и объёме текста менее 120 символов. Текст извлекается из первого доступного источника в порядке приоритета: выверенная расшифровка, Tesseract, распознавание средствами модели. Расшифровки в [overlays/scanned_pages.json](overlays/scanned_pages.json) адресуются хеш-суммой растра страницы, что исключает зависимость от имени файла и порядка страниц. При отсутствии всех источников формируется предупреждение с указанием документа и номера страницы; расчёт по неполным данным без уведомления не производится.

### Индивидуальные пороги признания связанной стороны

Досье KYC не содержит готового перечня связанных сторон. Оно содержит таблицу долей участия и отдельно сформулированный порог, который различается между заёмщиками: в публичном наборе встречаются значения 25.0, 30.0, 34.0, 35.0, 36.0, 38.0 и 40.0 %. Фиксация порога в коде приводит к ошибкам примерно в половине соответствующих ячеек.

Дополнительно досье может содержать две структурно схожие таблицы — доли голосующих прав и доли активов в залоге, — для которых действуют противоположные правила: доля активов в залоге ниже 50 % означает нахождение дочерней организации вне периметра обеспечения. Таблицы разбираются в границах своих разделов и не смешиваются.

### Отсутствующие значения в реестре

Две значимые операции не содержат суммы. Фактические значения раскрыты в документах: 486 204.19 — в служебной записке казначейства по счёту ACC-7807, 884 204.16 — в примечании 8.1 аудиторского заключения по счёту ACC-7808. Там же раскрыто обязательство по программе выходных пособий в размере 918 447.52, не отражённое отдельной проводкой; без его учёта совокупные обязательства по персоналу составляют 3 302 867.43 вместо 4 221 314.95.

### Валютный пересчёт

Таблица валютных курсов в наборе отсутствует. Аудитор раскрывает фактическое соотношение расчёта: счёт на 72 146.75 EUR урегулирован платежом 83 690.23 USD, откуда выводится курс 1.16. Проверка: `612 884.25 × 1.16 = 710 945.73`.

Курс определяется исключительно из документов. При отсутствии раскрытого курса сумма исключается из расчёта и формируется предупреждение; подстановка произвольного значения не выполняется.

## Правила расчёта

**Значение показателя.** Величина `actual` всегда положительна: расходы в реестре отражены отрицательными суммами, в расчёт принимается модуль. Округление выполняется по правилу `ROUND_HALF_UP` до двух знаков после запятой; сравнение с пороговым значением производится по неокруглённой величине.

**Условные ковенанты.** Если условие применения ковенанта не выполнено, статус устанавливается как `COMPLIANT`, при этом `actual` содержит фактическое значение показателя, а не `null`, в соответствии с требованиями конкурсного задания.

**Отсутствие данных.** Если показатель не может быть вычислен на основании доступных доказательств, расчётное ядро не подставляет нулевое значение. Формируется признак отсутствия результата, статус устанавливается как `BREACH` (соблюдение не подтверждено) и выводится предупреждение. Подстановка нуля признана неприемлемой: результат выглядел бы правдоподобно и не был бы обнаружен при проверке.

**Решающая операция.** Определяется тестом изменения вердикта. В число кандидатов включаются только операции, затронутые корректировкой аудитора, сопоставленные со связанной стороной или включённые в расчёт на основании признака из документа. Для каждого кандидата показатель пересчитывается без его участия; решающей признаётся операция, при исключении которой вердикт изменяется.

Ограничение круга кандидатов принципиально: согласно условию задачи, операция, лишь увеличивающая накопленную сумму, решающей не является. При отсутствии ограничения у агрегатного лимита решающей оказалась бы любая строка соответствующей статьи.

## Наблюдаемость и контроль качества

**Отчёт с обоснованиями.** Файл `report.md` формируется при каждом запуске и содержит по каждой ячейке: выбранный договор и перечень отклонённых редакций с указанием причины, дословную цитату пункта, пороговое значение, состав операций по статьям с идентификаторами, вычисленную формулу, вердикт и полный журнал теста изменения вердикта. Пример фрагмента:

```
### B1 п.6.1 — interest_cover
- Порог: >= 2.00
- Расчёт: revenue = 9 741 934.78 [TXN-B1-0026] ; opex = 6 166 592.66 [TXN-B1-0023] ;
          interest = 2 133 129.39 [TXN-B1-0020,TXN-B1-0033] => 1.68 против порога >= 2.00 => BREACH
- Доказательство: TXN-B1-0020
    - без TXN-B1-0020 (interest, 592 296.10): 2.32 -> COMPLIANT  => ВЕРДИКТ МЕНЯЕТСЯ
    - без TXN-B1-0030 (related_party, 307 018.08): 1.68 -> BREACH
```

**Сводка предупреждений.** По завершении работы выводится перечень позиций, требующих проверки человеком: отсутствие действующего договора, нераспознанная растровая страница, нераскрытый валютный курс, неопознанный тип ковенанта, невычислимый показатель. Конвейер не подставляет значения по умолчанию без уведомления.

**Журнал выполнения.** Файл `logs/run.log` содержит полную трассировку: решение по каждому документу с обоснованием, порог из каждого досье, результат сопоставления каждого контрагента с указанием степени совпадения, состав статей по каждому заёмщику.

**Валидация результата.** Перед записью структура результата сверяется с шаблоном по составу сценариев, пунктов и полей каждой ячейки; проверяются допустимость статуса и числовой тип значения. Расхождения выводятся как предупреждения.

## Тестирование

Набор из 40 модульных тестов охватывает расчётное ядро и разбор документов.

| Файл | Область покрытия |
|---|---|
| [tests/test_engine.py](tests/test_engine.py) | Округление, знак величины, границы порога, условные ковенанты, деление на ноль, отсутствие раскрытой константы, квартальная фильтрация |

Отдельными тестами закреплены проектные инварианты, нарушение которых приводит к скрытым ошибкам: пороговое значение читается из досье и не фиксируется в коде; нераскрытая константа не заменяется нулём; условный ковенант при невыполненном условии возвращает фактическое значение показателя.

## Известные ограничения

### Счёт ACC-7805, пункт 6.1 — 0.5 балла из 1.0

Действующая редакция договора за отчётный год в наборе отсутствует; доступна только редакция 2024 года с отметкой о неприменении. Пороговые значения пунктов 6.2 и 6.3 из этой редакции воспроизводят эталон точно: 8 214 663.28 при минимуме 7 500 000.00 и 273 418.66 при лимите 260 000.00.

Показатель пункта 6.1 определён как отношение капитальных затрат Группы к EBITDA заёмщика и требует консолидированной величины по группе, которая не раскрыта ни в одном документе набора. Проверка гипотезы о выводимости эталонного значения из реестра дала 183 формально подходящие комбинации сумм, ни одна из которых не имеет экономического смысла, что указывает на подгонку под шум, а не на восстановление зависимости.

Реализованное поведение: соблюдение не подтверждается, устанавливается статус `BREACH`, выводится приближённое значение и предупреждение о необходимости проверки человеком. Статус соответствует эталону, значение — нет. Подбор числа под эталон не выполнялся ввиду отсутствия документального обоснования.

### Счёт ACC-7804, пункт 6.3 — 0 баллов

Расчёт даёт `288 417.52 / 7 004 318.47 = 0.041177` при лимите 0.04x, что квалифицируется как нарушение; эталон содержит статус соблюдения.

Оба входных значения подтверждаются смежными ячейками того же заёмщика: та же величина выручки 7 004 318.47 обеспечивает точное совпадение по пункту 6.1 (0.33), а платёж 288 417.52 относится к единственному контрагенту, проходящему порог 30.0 % из досье.

Ячейка по счёту ACC-7808 устроена идентично: `342 118.65 / 7 884 663.19 = 0.043391` при том же лимите 0.04x, при этом эталон квалифицирует её как нарушение. Сравнение по округлённому значению сделало бы корректной первую ячейку и некорректной вторую; сравнение по неокруглённому значению даёт обратный результат. Суммарный балл в обоих случаях одинаков.

Принято решение сохранить математически строгое сравнение по неокруглённой величине. Настройка правила под конкретную ячейку отклонена как ведущая к переобучению на публичном наборе.

## Эксплуатация на новом наборе данных

1. Распаковать архив и выполнить `python main.py --data <каталог> --out submission.json`.
2. Изучить сводку предупреждений в конце вывода. Сводка перечисляет позиции, по которым агенту не хватило документальных оснований.
3. Устранить выявленные пробелы. Типовые действия: добавление расшифровки растровой страницы в [overlays/scanned_pages.json](overlays/scanned_pages.json) либо правила распознавания нового типа ковенанта в `SPEC_LIBRARY` модуля [src/covenants.py](src/covenants.py).
4. Повторить запуск и сверить обоснования в `report.md`.

Опциональные компоненты распознавания растровых страниц подключаются автоматически при их наличии в среде: Tesseract с языковыми пакетами `rus` и `eng`, либо распознавание средствами модели при заданной переменной окружения `ANTHROPIC_API_KEY`. Основной сценарий работы обоих компонентов не требует.
